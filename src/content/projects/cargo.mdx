  problem:
    - Staff need the fleet, bookings, payments and revenue under control
    - Customers only need to see what's genuinely free and reserve it
    - CarGO serves both from one MySQL schema behind two role-gated entry points
  built:
    - Role-gated customer and admin apps over one schema, plus a super-admin
      tier that gates admin account management
    - The booking lifecycle end to end - conflict-checked checkout, admin
      pickup and return confirmation, automatic late fees at the daily rate
    - Payments with per-day add-ons, seven payment methods and a gateway stub;
      cars soft-archive so booking history survives their removal
    - Prepared statements throughout, a CSRF token on every state-changing
      POST, hardened sessions, and 29 PHPUnit tests over the shared helpers
  hardPart:
    - "Admin car uploads had to survive shared hosting's memory ceiling - GD blowing
      it mid-decode is an uncatchable fatal, not a recoverable exception"
    - Nothing decodes blind - getimagesize() reads dimensions first, then a
      byte-cost estimate rejects oversized images up front with the real limit
    - Under the ceiling, memory_limit is raised only as far as that image needs,
      then downscaled to 1600px with 400/800px JPEG and WebP derivatives for srcset
    - Every stage degrades instead of failing - missing GD, missing WebP, or a
      derivative write error all fall back to serving the plain original

CarGO is a car rental management system with two distinct roles: an admin side
for managing the fleet, bookings and customers, and a customer side for
browsing availability and making a reservation.
